# Wave 2 integration notes

Branches `wave2-jobs`, `wave2-providers`, `wave2-profile`, `wave2-ingest`, `wave2-progress` merged into `main` in that order, then one integration commit. Every branch was lint- and test-green before merging; after merging, `just lint`, `just test` (417 Python, 82 web) and `just integration` (13 Postgres tests) are green.

## Changes made at merge

- `apps/api/app/main.py`: `create_app(*, schema_guard=True, background=True)`. The lifespan wraps `yield` in `start_refresher(app)` when `background` is true. The shared test fixtures build the app with `background=False`: with `TestClient(app)` running the lifespan, the refresher's first sweep raced the request on the single in-memory SQLite connection ("cannot commit transaction - SQL statements in progress"). Postgres is unaffected. Tests that need the refresher start it directly (`tests/services/test_provider_refresher.py`).
- `apps/web/src/api/client.ts`: `apiPut` added. `PATCH /api/settings/providers` still exists and the providers page still uses it.
- `apps/api/app/services/sources.py`: `enqueue_ingest` calls `app.services.jobs.enqueue`; `SourceService.delete` cancels through `app.services.jobs.cancel`. Consequence: every ingest job carries the `status`/`queued` event that `enqueue` records before the handler's `sources.updated` events.
- `apps/api/app/api/v1/events.py`: a `job_events` row whose `kind` contains a dot (`sources.updated`) is forwarded as its own SSE type with `data` as payload, after `jobs.updated`; other kinds are forwarded as `jobs.event`. `sse_message` accepts a `BaseModel` or a dict. Rule for later sections: to push a non-job event to the web, write a `JobEvent` with a namespaced `kind` (`String(16)`) and commit; register the type in `invalidations.ts`.
- `apps/api/app/services/progress.py`: `promote_achieved_targets` promotes through `app.services.profile.promote_target`; the profile version bumps once per promoted target (the learner-profile spec says every change increments it). The duplicate `_add_current_skill` is gone.
- `justfile` / `.github/workflows/ci.yml`: one `integration` recipe and one `integration` CI job (pgvector service, `BRAINBENCH_DATA` for the embedding model) run `pytest -m integration apps/api/tests/integration`. The per-section recipes (`jobs-integration`, `providers-integration`, `ingest-integration`) remain for local use; sections add tests under `tests/integration/`, not new CI jobs.
- `uv.lock` and `bun.lock` regenerated at the root.

## Facts for wave 3 (sections 6, 7, 9)

- Read `notes/wave2-jobs.md`, `wave2-providers.md`, `wave2-profile.md`, `wave2-ingest.md`, `wave2-progress.md` for the public surfaces. Short index:
  - Jobs: `app.services.jobs.enqueue(session, type, payload, *, dedupe_key=None, priority=0, run_after=None)` (returns the active job holding `dedupe_key`), `cancel`, `get_job`, `list_jobs`, `list_events`; `app.services.job_events.record_event(session, job, kind, *, message=None, data=None)`; handler registration `@register("<type>")` in `app/jobs/<type>.py` plus one import line in `app/jobs/__init__.py`; `@register_claim_gate("<type>")` for claim-time budget checks; `JobContext.save_checkpoint/progress/cancelled` and `register_kill_hook` (see the jobs notes); `JobSkipped` for the `skipped` outcome.
  - Providers: `app.services.providers.model_for(session, task_class)` returns the routed Strands `Model` (records `provider_usage` per call with that task class), `ensure_provider_for(session, task_class)` to call before enqueueing or accepting a tutor message, `provider_limit_from(exc)` to convert a throttle (bare or wrapped in Strands' `EventLoopException`) into `ProviderLimitReached`, `ProviderRetryStrategy` for agents. Task classes are strings; the routing UI lists the ones `GET /api/settings/providers` knows, so register new task classes where the providers notes say.
  - Profile: `require_profile`, `get_profile`, `read_profile(session, profile) -> ProfileRead`, `promote_target`.
  - Ingestion: `app.services.search.search_chunks(session, query, k, *, source_ids=None, topic_id=None) -> list[ChunkHit]`, `nearest_chunks(session, vector, k, ...)`, `app.services.embeddings.embed_texts/embed_query`.
  - Progress: `topic_status`, `topic_stats`, `session_history`, `mastered_topic_ids`, `current_plan`, `plan_topics`, `promote_achieved_targets` (call after writing a new plan version), `LogSessionDialog` at `apps/web/src/pages/progress/components/LogSessionDialog.tsx`, which invalidates `['progress']` and `['topics', topicId]`.
- Web conventions in place: `sections` in `routes.tsx` (providers, sources, profile, jobs, progress), `jobTypeInvalidations[type] = (job) => QueryKey[]` in `invalidations.ts` for refreshing a section's queries when its jobs change, `apiGet/apiPost/apiPatch/apiPut/apiDelete`, test harness and `*Mock.ts` pattern under `apps/web/tests/support/`.
